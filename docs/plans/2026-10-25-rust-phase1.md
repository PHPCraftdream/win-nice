# wnice Rust phase 1 — design notes (spec of record)

Crate `wnice` v0.2.2, edition 2021, Windows-only (x86_64-pc-windows-msvc).
Deps: `windows-sys` (target-specific under `cfg(windows)`), features enabled
only as needed: Win32_Foundation, Win32_System_JobObjects,
Win32_System_Threading, Win32_System_Memory, Win32_System_SystemInformation.

## Handle (RAII)

`pub struct Handle` wraps a windows-sys HANDLE (isize). Not Clone. `raw()`
accessor; `from_raw` constructor for RealSys only. `Drop` calls CloseHandle
exactly once, directly via windows-sys — CloseHandle is intentionally NOT part
of the Sys trait (RAII owns closing).

## Sys trait (object-safe, no generics)

All fallible calls return `Result<_, u32>` (u32 = GetLastError-style code).

- create_job_object() -> Result<Handle, u32>
- set_information_job_object(&Handle, info_class: u32, bytes: &[u8]) -> Result<(), u32>
- create_process(app_name: Option<&str>, cmdline: &str, creation_flags: u32) -> Result<Child, u32>
  where `Child { process: Handle, thread: Handle, pid: u32 }`
  (bInheritHandles=true, lpApplicationName = the resolved path, NULL env/cwd)
- assign_process_to_job_object(job: &Handle, proc: &Handle) -> Result<(), u32>
- resume_thread(t: &Handle) -> Result<(), u32>  // prev count 0xFFFFFFFF = fail
- create_waitable_timer() -> Result<Handle, u32>  // manual-reset, anonymous
- set_waitable_timer(h: &Handle, due_time_filetime: i64) -> Result<(), u32>
  // one-shot, no APC, fResume=false
- wait_for_multiple_objects(&[&Handle], wait_all: false) -> Result<u32, u32>
  // INFINITE timeout; returns index minus WAIT_OBJECT_0; 0xFFFFFFFF -> Err
- get_process_times(p: &Handle) -> Result<i64, u32>  // exit time as 64-bit FILETIME
- get_exit_code_process(p: &Handle) -> Result<u32, u32>
- terminate_process(p: &Handle, code: u32) -> Result<(), u32>
- terminate_job_object(j: &Handle, code: u32) -> Result<(), u32>
- global_memory_status_ex() -> Result<u64, u32>  // total physical bytes
- logical_processor_count() -> u32  // GetSystemInfo; infallible
- system_directory() -> String  // GetSystemDirectoryW

## RealSys / errors

`pub struct RealSys;` implements Sys with windows-sys calls. Rules: every
fallible call checked; GetLastError captured IMMEDIATELY after the failing
call; error type is the bare u32 code. Messages formatted by callers via:

```rust
pub fn win32_err(fn_name: &str, code: u32) -> String { format!("{fn_name} failed: {code}") }
```

## run

`pub fn run(cfg: &Config, sys: &dyn Sys) -> i32` lives in `src/run/mod.rs` and is
implemented: resolves the command, creates the job, applies limits, launches
the child suspended into the job, resumes it, then enforces timeout/memory/
exit-code handling and returns the child's exit code (nonzero on internal
errors).

## Command resolution (bare names)

A first command token containing a path separator is used verbatim. A bare
name is resolved by `launch::resolve_bare_name`, never by Windows:
`launch::path_dirs` keeps only ABSOLUTE PATH entries that are not the current
directory (empty, `.`, `.\`, relative entries and the cwd itself are dropped).
For each dir in order, the name as-is (when it already ends in a launchable
extension) and then name + each launchable extension in PATHEXT order (only
`.com`/`.exe`/`.bat`/`.cmd`; default `.com;.exe;.bat;.cmd`) is tried. The
first existing file is passed to `Sys::create_process` as lpApplicationName
(`.bat`/`.cmd` go through cmd.exe). No hit means
`wnice: '<name>': command not found (searched PATH; the current directory is
never searched)` and exit code 127.

## main (multicall dispatcher)

argv[0] file stem, case-insensitive, `.exe` stripped.
- `wnice` -> parses args via `cli`, builds a `Config`, and calls `run()`;
  errors go to stderr with `wnice: ` prefix, exit code from `run()`.
- legacy names {idle, belownormal, abovenormal, high, realtime, capc, capt,
  capm, caps, capn, cy, cx, admin, uiup} ->
  `wnice: frontend '<stem>' is not implemented yet`, exit 2.
- anything else -> usage error, exit 2. No panics.

## Modules

`cli`, `limits`, `launch`, `run` are implemented (no placeholder stubs);
`run` holds `run()`, `launch` the process/job setup, `limits` the limit
serialization, `cli` parsing and usage text.

## Limit serialization

Limit structures are windows-sys structs (JOBOBJECT_EXTENDED_LIMIT_INFORMATION,
JOBOBJECT_CPU_RATE_CONTROL_INFORMATION) built with `std::mem::zeroed`, then
never viewed as raw memory (`#[repr(C)]` padding is not guaranteed
initialized): `limits::extended_bytes` and `limits::cpu_rate_bytes` write
each field at its `offset_of!` into a zeroed buffer, which is what
set_information_job_object receives.
