## Findings

### P2 — docs-sync тест допускает ложный pass при повторном расхождении README и SKILL.md

Файлы: `test/docs-sync.test.js:7-19`, `README.md:99-107`.

Новый тест проверяет лишь наличие строки `fails closed` в каждом документе.
Однако README использовал эту фразу ещё до исправления argument-safety раздела —
в независимом описании `CREATE_BREAKAWAY_FROM_JOB`:

> breakaway-allowed flag, that fails closed

Это подтверждается содержимым README в старом `c89a29d`. Следовательно, если
argument-safety текст README снова откатится к старому поведению, а `SKILL.md`
останется новым, обе проверки `includes('fails closed')` продолжат проходить.
Тест заявляет защиту от расхождения, но фактически защищает только наличие очень
общей фразы где угодно в файлах.

Рекомендация: проверять несколько специфичных признаков именно `%`-контракта,
например сочетание:

- `if any argument contains '%'`;
- `exits with code 1`;
- `the command never reaches cmd.exe`;

Либо выделить канонический общий fragment/source и генерировать соответствующие
разделы README и `SKILL.md` из него. Минимальный тест должен предварительно
извлекать секции `Argument handling` / `Argument safety`, а не искать текст по
целому документу.

### P2 — интеграционные тесты могут ждать дочерний процесс без верхней границы

Файлы: `test/win-nice.Tests.ps1:207-221`, `.github/workflows/ci.yml:30-34`,
`.github/workflows/publish.yml:44-48`.

Тест непропагации повышенного приоритета запускает `cmd /c ping -n 3`, а затем
вызывает `$c.WaitForExit()` без timeout. В текущем прогоне case `high` занял
206.36 секунды вместо ожидаемых примерно трёх, хотя в итоге прошёл. Весь Pester
run занял 345.78 секунды, тогда как README обещает примерно 1–2 минуты.

Любая проблема запуска/завершения `ping` способна удерживать CI job до общего
лимита GitHub Actions. В publish workflow это блокирует или существенно
задерживает выпуск, не выдавая локализованную ошибку теста.

Рекомендация:

- заменить бесконечный `WaitForExit()` на `WaitForExit(timeoutMs)`;
- при timeout завершать дочерний процесс в `finally` и падать с понятным
  сообщением;
- использовать более детерминированный короткоживущий PowerShell probe вместо
  сетевой утилиты `ping`;
- установить `timeout-minutes` для integration step/job в CI и publish workflow.

Такой timeout не должен применяться к пользовательским launcher-командам: их
бесконечное ожидание является частью контракта. Речь только о тестовых probes.
