`capm`'s size-argument syntax went through two user-driven redesigns during this stretch. It started as `%`/MB/GB/bare-decimal-fraction (0.01-1.0). The user then asked to remove `%` entirely after a real reported bug: chaining tools by bare name (e.g. `cap 50 capm 25% ...`) resolves through each tool's `cmd.exe`/`PATHEXT` fallback, and a literal `%` anywhere on that line trips the universal fail-closed check — so `cap 50 capm 25% ...` failed while `capm 25% cap 50 ...` worked, an order-dependent foot-gun. The user then asked to go further and unify `capm`'s bare-number form with `cap`'s own `<percent 1-100>` convention exactly: a bare integer (no suffix) is now *always* percent, `m`/`M`/`g`/`G` are required for MB/GB, and there is no `%` character and no decimal-fraction form left in the interface at all.
