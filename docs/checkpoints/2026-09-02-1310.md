## Decisions
- `capm` uses `JOB_OBJECT_LIMIT_JOB_MEMORY` (aggregate, whole-job) rather than `JOB_OBJECT_LIMIT_PROCESS_MEMORY` (per-process) - matches `cap`'s CPU% and `pint`'s affinity semantics: one ceiling for the whole tree, not a per-process limit.
- First npm publish used a classic `NPM_TOKEN` (npm Trusted Publisher literally cannot be configured for a package that doesn't exist yet); switched to OIDC-only once the package existed and Trusted Publisher was configured on npmjs.com - a deliberate two-phase rollout, not a workaround left in place.
- Moved (deleted + recreated) the `v0.1.0` git tag twice during publish debugging rather than bumping the version - justified because the broken states never actually reached the npm registry each time, so nothing was "released" under them.
- Switched `package.json`'s `test` script from `node --test` (default discovery) to an explicit space-separated file list, after discovering the former silently vacuums up test files from `/wrush`'s own `worktrees/` directory.
- Fixed both capm functional-test bugs found during development (string-format braces, shared-Job-budget headroom miscalculation) rather than weakening or skipping the tests, per the standing "fix test failures on the spot" rule.
